How each requirement is covered

Stack and tables: Next.js App Router, TypeScript and Postgres. Migrations create users, workspaces, memberships, projects, notes and summaries. The seed has two workspaces (Acme and Globex) and five users with different roles.
Isolation: the app connects as a restricted app_user with no RLS bypass. Each request sets the verified user id inside its transaction, and row-level security is enabled on every table.
Fail closed: a missing or malformed user id returns zero rows. Restrictive policies mean even a sloppy USING (true) policy can’t leak across workspaces, and a test proves it.
Least privilege: column-level grants keep workspace_id and password_hash untouchable, and a composite foreign key stops a child row from sitting in a different workspace than its parent.
Auth: email and password with a session cookie. The server derives the user itself, and request schemas reject unexpected keys.
Roles: viewers read, editors create, edit and summarize, owners also invite. This is checked in the services and again in the database.
Summarize: LlmProvider interface with a mock. Note text is sent only as JSON data, never in the system prompt. Output must be exactly one JSON object matching a strict schema, with one retry. Only validated output is stored, and it is rendered as plain text.
Edge cases: a foreign id, a made-up id and a malformed id all return the same 404, whether it’s in the URL, the body or a direct SQL call. The seed includes an Acme note containing “ignore previous instructions”, and the mock returns malformed output on the first attempt of every summarize call.
